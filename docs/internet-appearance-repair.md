# 2026-10-19 公网形象同步修复（0.6.3）

## 目标与依赖
用户在本机换网后要求实测联网游戏，并指出双方只能看到自己的形象。随后授权先修复大乱斗。基线为新鲜 origin/main 5a4b97e，独立分支 codex/internet-appearance-repair；已具备支持完整动画 SDK 的宿主及两台不同网络的实际 Mac，无待补材料或产品决策。

## 原因与修改
原完整动画编码允许 900 KiB。真实宿主上奇奇 20 帧及待机数据共 478,163 bytes，而宿主为了不阻塞操作消息将资源传输限为 12 KiB/s，单方向形象需要约 39 秒；真实公网测试中开局后 20 秒双方仍显示对方的默认模型。另一轮出现 receipt_timeout；该单次网络错误的直接诱因未独立定位，不能只用总传输耗时解释逐帧 ACK 超时。

src/walk-animation.js 按统一透明边界压缩空间尺寸及 WebP 质量，将完整动画限制为 64 KiB。保留每一帧、原顺序、fps、loop 和 face，不修改格斗、预测或宿主传输协议。内置角色实测奇奇 65,112 bytes / 20 帧、捏捏 56,221 bytes / 18 帧。取舍为传输用帧的空间细节减少；保留原同一裁切与脚底，未用待机图冒充走路动画。超过上限的复杂自定义形象仍走既有同宠静态回退，本轮没有宣称覆盖所有自定义形象或 3D。

## 验证与归属
扩充既有 test:host:walk，同时验证奇奇和捏捏的完整注册帧数、64 KiB 上限、真实材质变化、左右方向、松开恢复待机、跳跃与攻击中断走路、所有窗口首帧前隐藏。仍归 test:host / test:delivery；没有额外创建平行的游戏测试文件。旧版宿主可显式设置 BRAWL_LEGACY_CONSENT=1，新宿主按已声明权限直接使用。

- test:rules：349 + 11 + 8 + 13 + 3 + 43 + 10 + 3 项全部通过；包含网络、状态、动作与走路。
- test:artifact：2/2。HTML 与构建回执精确摘要一致，协议仍为 pet-brawl v3。
- test:host:walk：两角色全部通过，真实隐藏应用及 CDP 按键。
- 两台实体 Mac 在不同网络、LAN 关闭、真实测试账号与公网 WSS 上，通过真实文件选择及“发送并一起玩”将候选 HTML 送达另一块磁盘，双方摘要一致。两边均显示捏捏和奇奇，开局观测首个采样即均为 sprite；同一路径旧版超过 20 秒仍未同步。两屏分别验证所有注册 walk 帧及材质变化、真实移动、五次攻击、两次掉落后恢复、相同结算、双方再来一局、退出传播及无未处理异常；本轮没有复发 receipt_timeout。进程退出并服务端登出测试账号。

原始证据在游戏本地 artifacts/internet-repair/、artifacts/walk-host/；实体候选验收脚本为已退役的现场适配器，不作为无人维护的新门禁。长期故障断言扩充在既有 test:host:walk。

## 发现与防再犯
- 用户在截图验收阶段发现对方形象缺失；此前网络验证只证明入场和输入收发，没有证明双方实际材质均为对应宠物。本次补上输出、真实动画与传输体积断言。
- 扩测时首次错误地把捏捏也写成 20 帧，实际注册为 18 帧。修正为读取实际注册帧数后逐一核对，保留失败记录；没有按错误夹具改产品。
- 不新增宿主 SDK API，不改变公开类型、脚手架或市场登记；宿主只同步精确构建产物和内置资源清单。未发布宿主下载地址、凭据或用户素材。
